# Chore Quest — Redesign Plan (v2)

Date: 2026-11-08 · Status: for approval · Scope: student POC, looks good + fun > completeness

Hypothesis to validate: **an RPG reward loop motivates kids to do chores.**
Every feature below is picked because it maps to a known motivator:
immediate feedback, visible progress, earned rewards the kid chooses, streaks, and a bit of surprise.

---

## 1. The reworked concept: "Hero of the Keep"

The kid is a **hero** who protects a small medieval **keep** (their home base).
Chores are **bounties** posted on the keep's **bounty board** by the **Quest Giver** (parent).
Each bounty is a monster lurking outside the walls. Slaying it (doing the chore) earns **gold** and **XP**.

- **Gold** = currency. Parent sets the amount per quest. Spent at the **Merchant** (parent-made shop: "Stay up 30 min", "Pick dinner", "1h Switch").
- **XP** = lifetime progress. Never goes down. Levels the hero up (titles) and upgrades the keep: tent → hut → cottage → house → fort → castle (existing sprites).
- **Streak** = days in a row with at least one quest done. Shown as a torch flame that grows.
- ~~**Loot chest**~~ — removed 2026-11-09: random rewards felt too close to gambling for kids. Approval pays exactly the quest's gold.

### What changes vs. today, and why

| Today | v2 | Why |
|---|---|---|
| Points from size S/M/L, decay when late | **Parent sets gold per quest** (presets 5/10/25/50 or custom). No decay. | Kids understand a fixed price. Parents asked to set the amount. |
| Base HP drains, shop locks at 0 HP | **HP removed.** Overdue monsters just look angrier (red eyes, shake). | Punishment stresses kids and complicates the test. Rewards only, so the hypothesis is cleaner. |
| "Points", "tier" | **Gold**, **XP + level + title** (Squire → Knight → Champion → Paladin → Lord) | Two clear meters: spend vs. grow. |
| No shop | **Merchant** with parent-defined rewards, purchase → parent delivers | Core of the brief. |
| One-off quests | **Repeat: none / daily / weekly** | Chores recur; parents shouldn't re-type "make bed" daily. |
| Plain monospace UI | **Full pixel-art RPG UI** (section 3) | The brief. |

## 2. Screens

### Kid (bottom nav, 4 pixel icons)

1. **Keep** (home): Phaser scene, a day/night sky that follows the real clock, the keep sprite for the current tier, the hero standing at the gate, and monsters for open quests around it. Top HUD: hero portrait + level + XP bar, gold purse, streak torch. Tap a monster → its bounty card.
2. **Bounty Board**: wooden board with parchment notes pinned to it. Each note shows the monster sprite, chore name, gold, and time left. "Today" first, then "Later".
3. **Merchant**: shelf of reward cards with icon and price. Can't afford one → shows "need 12 more gold". Buy → confirm → coin animation.
4. **Bag**: rewards bought (waiting / delivered), plus trophies (level-ups, longest streak).

**Slay moment** (most important for the "fun" feeling):
tap **Slay!** → hero dashes to the monster → slash + white flash + screen shake → monster turns to smoke → "+25 gold" floats up, coins arc into the purse → monster becomes a **stunned** marker (chains + "awaiting the Quest Giver") until approved.
On approval, the kid's next app open plays the XP bar filling, level-up fanfare if earned, and a chest opening if it's the 3rd one.
Small 8-bit sound effects (WebAudio, no files) + phone vibration. Mute toggle.

### Parent ("Quest Giver", 4 tabs, plain + fast, light pixel styling)

1. **Approvals** (badge count): claimed quests and shop purchases in one list. One tap ✓ / ✗.
2. **Quests**: list per kid. "+ New quest" opens a **template grid** (Make bed, Tidy room, Dishes, Trash, Laundry, Vacuum, Feed pet, Homework, Custom), each with an icon. Pick → kid → gold → repeat → done. Three taps for the common case.
3. **Merchant**: add/edit rewards (name, icon from a set of ~12, price). Starter rewards prefilled when the family is created.
4. **Family**: kids, invite code (big + copy button), and a **simple stats card**: quests done this week per kid, average time from post → done, streaks. Directly useful for the hypothesis write-up.

### Onboarding

Title screen with logo art: "**I'm a Hero**" / "**I'm the Quest Giver**".
The kid picks one of 4 hero sprites when joining (replaces the text avatar).

## 3. Visual design

- **Font:** "Pixelify Sans" (Google Fonts) for UI and "Press Start 2P" for numbers/titles only (it's hard to read in long text).
- **Palette:** warm medieval: wood browns, parchment cream, gold `#f4c542`, deep night blue, moss green, blood red for danger. Defined as CSS tokens.
- **Panels:** wood frames and parchment fills drawn with CSS pixel borders (`box-shadow` stepping + `image-rendering: pixelated`), so no 9-slice images are needed. Chunky buttons with a 2px "pressed" offset.
- **Icons/art from PixelLab** (MCP is connected): 4 hero sprites (idle + attack frames), gold coin, chest (closed/open), streak torch, ~12 reward icons, 9 chore template icons, nav icons, title logo, village background. Reuse the existing 7 monsters + 6 keep tiers.
- **Motion:** idle bob on monsters/hero, coin sparkle, button press squish. All CSS/Phaser tweens.

## 4. Tech changes (same stack: React + Phaser + Supabase on Vercel)

**DB — one new migration:**
- `quests`: add `gold int`, `repeat` (`none|daily|weekly`); keep `size`/`category` only for picking the monster sprite (size derived from gold: <15 small, <40 normal, else boss).
- `members`: rename meaning — `lifetime_points` → XP, `wallet_points` → gold (keep columns, rename in UI only, to save migration work); add `streak`, `best_streak`, `last_done_on`, `approvals_count` (for chests).
- New `rewards` (family, name, icon, price, active) and `purchases` (reward, kid, price, status `pending|delivered`, timestamps).
- RPCs: `review_claim` updated (award gold+XP, streak, chest roll, respawn next copy if repeating); new `buy_reward`, `deliver_purchase`.
- `create_family` seeds 4 starter rewards.

**Front end:** new kid shell with nav + 4 screens, reworked Phaser `HomeScene` (hero, sky, slay animation), parent tabbed shell, shared pixel UI kit (`Panel`, `PixelButton`, `GoldAmount`, `Icon`). `core/` rules shrink (no HP/decay); add level/title math.

**Tests:** keep it light. Update existing tests that break; add small unit tests only for the core math (levels, streak). No new pgTAP beyond fixing broken ones.

## 5. Build order (each step leaves a working app, deployed by pushing to main)

1. **Pixel UI kit + art** — fonts, tokens, panels, buttons; generate PixelLab assets.
2. **DB migration + data layer** — gold, repeat, rewards, purchases, streak, chest.
3. **Parent side** — tabs, templates, approvals, merchant editor, stats.
4. **Kid side** — nav, Keep HUD, Bounty Board, Merchant, Bag.
5. **Juice** — slay animation, approval reveal, level-up, chest, sounds, vibration.
6. **Polish pass** — phone-size check in the browser, fix rough edges, deploy.

Before testing on phones, the Supabase project has to be **restored** in the dashboard (it's paused).

---

## 6. Out of scope (could do later)

Sibling leaderboard (can demotivate the younger kid), photo proof, cosmetic keep decorations shop, push notifications, achievements beyond level/streak, multiple languages.

## 7. Decisions for you

1. **Remove base HP / damage?** Recommended: yes (rewards only, angrier-looking overdue monsters).
2. **Remove late-decay of gold?** Recommended: yes (fixed price set by parent).
3. **Loot chest every 3rd quest?** Recommended: yes, bonus 5–20 gold.
